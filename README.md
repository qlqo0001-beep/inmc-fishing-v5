# inmc-fishing

5세대 낚시 플러그인. 등급별 미니게임 · 도감 · 트로피 힘겨루기 · 대회를 갖췄습니다.

2세대 `InMc-Fishing`(Java 108파일 20,112줄 · 테스트 0개)을 Kotlin 으로 **전면 재구성**한
것입니다. 원본 폴더(`낚시/`)는 건드리지 않았고, 이름과 기능만 계승했습니다. 플러그인 이름이
`inmc-fishing` 이라 데이터 폴더도 `plugins/inmc-fishing/` 이고 원본과 공존할 수 있습니다.

---

## 필요한 것

| | |
|---|---|
| 서버 | Paper 1.21+ |
| 필수 | **`inmc-core`** — Kotlin 런타임과 공용 프레임워크를 들고 있습니다 |
| 선택 | Vault(참가비·보상) · MMOItems · ItemsAdder/Nexo/Oraxen · PlaceholderAPI · WorldGuard |

선택 연동은 없어도 켜지고, 있으면 저절로 붙습니다(늦게 켜져도 붙습니다). MMOItems ·
ItemsAdder/Nexo/Oraxen 은 **리플렉션**으로 닿고(`ContractTest` 가 컴파일 결과를 바이트 단위로
훑어 지킵니다), PlaceholderAPI · WorldGuard 는 설치를 확인한 뒤에만 그 클래스를 건드립니다.

## 한 번 낚는 동안 일어나는 일

```
낚싯대를 던짐
   └ 기능 켜짐 / 월드 / WorldGuard 구역 / 등록 낚싯대 확인   (FishingListener)
입질
   └ 등급 추첨 → 물고기 추첨 → 대어 → 더블 → 크기 → 트로피   (RollEngine)
   └ 미니게임을 켰으면 L/R 클릭 게임        (ClickGame)
      껐으면 등급별 대기 시간 뒤 자동        (피로도 소모)
성공
   └ 트로피면 힘겨루기                     (Fight + FishAI — 2세대 원본 그대로, fight.yml)
   └ 아이템 지급 → 도감 → 랭킹 → 대회       (CatchService)
```

**추첨은 입질 순간에 이미 끝나 있습니다.** 미니게임은 그 결과를 받을지 말지를 정할 뿐입니다 —
클릭을 잘한다고 등급이 오르지 않습니다. 순서가 반대면 미니게임 난이도를 정할 수가 없습니다
(난이도가 등급에서 오기 때문입니다).

## 설정 파일

| 파일 | 무엇 |
|---|---|
| `config.yml` | 기본 동작 · 확률 · 도감 · 어망 · 손질 · 피로도 · 보상 |
| `fight.yml` | **힘겨루기** — 2세대와 같은 파일(키·구조·값). 옛 파일을 그대로 넣어도 됩니다 |
| `grades.yml` | 등급(F~S). **enum 이 아니라 설정값**이라 늘리고 줄일 수 있습니다 |
| `modifiers.yml` | 월드·바이옴·날씨·시간·권한 5축 **곱연산** 보정 |
| `messages.yml` | 메시지. 코드의 기본값 표와 키가 정확히 일치해야 합니다 |
| `fish.yml` | 낚을 수 있는 것 70종 |
| `rods.yml` | 낚싯대 10종 |
| `baits.yml` | 미끼 11종 |
| `potions.yml` | 피로회복 물약 7종 |
| `fillet-items.yml` | 생선살 21종 (7등급 × 3) |
| `tournaments.yml` | 대회. **여러 대회가 동시에** 돌 수 있고, 열리기 전엔 사전 신청을 받습니다 |
| `collections.yml` | 도감 보상 다섯 갈래 |
| `worldguard.yml` | WorldGuard 구역별 낚시 금지 · 등급 배수 (2세대와 같은 형식) |
| `item-format.yml` | 지급하는 낚싯대의 능력 로어 서식 (2세대와 같은 키) |

저장 파일: `players/<uuid>.yml`(도감·어망·피로도·손질대·연습 모드) ·
`tournaments/active.yml`(진행 중인 대회와 사전 신청) · `tournaments/history/<id>.yml` ·
`tournaments/winners.yml`(**2세대와 같은 형식** — 옮겨 놓으면 우승 기록이 이어집니다).

PlaceholderAPI: `%inmcfishing_<키>%` — 2세대와 같은 식별자·키·기본값입니다
(도감·피로도·랭킹·`best_size_<물고기>`·힘겨루기 `fight_*`). 힘겨루기 화면은 `fight.yml` 의 `hud.mode` —
배포값 `vanilla`(2세대 1.6.0 과 같다)는 상태 타이틀 · 보스바 · 액션바를 그립니다. `betterhud` 면 보스바·액션바를 그리지 않고
BetterHud 가 `fight_*` 로 그립니다 — 상태 타이틀(상태 · 남은 초 · 할 일)은 어느 모드든 뜹니다.

아이템 파일 다섯은 **`/낚시 관리` 에서 전부 편집할 수 있습니다.** 손으로 고쳤다면
`/낚시 리로드` 를 실행하세요.

## 아이템 등록 — core 의 `StoredItem`

2세대는 `use-type: vanilla|mmoitems` 두 갈래였고, 그래서 ItemsAdder 아이템이나 직접 만든
아이템은 **아예 등록할 수 없었습니다.** 지금은 네 종류가 같은 길로 들어옵니다.

```yaml
item: "minecraft:cod"          # 바닐라
item: "mmoitems:MATERIAL:TUNA" # MMOItems
item: "itemsadder:내물고기"     # ItemsAdder / Nexo / Oraxen
mode: SNAPSHOT                 # 손에 든 것을 그대로 (참조를 못 만드는 수제 아이템)
```

`REFERENCE` 는 매번 원본에서 다시 만들고, `SNAPSHOT` 은 등록한 순간으로 고정합니다.

**커스텀아이템이 있으면 그림이 저절로 붙습니다.** 물고기 · 생선살 · 미끼 · 낚싯대가 커스텀아이템으로 옮겨 가면서, 커스텀아이템에
들어 있는 16x16 그림과 등급(물고기 F~S → 일반~신화)이 입혀집니다. `/커스텀아이템 리팩 빌드` 후 팩을 다시 올리면 보입니다.
**손에 들고 GUI 의 등록 버튼을 누르면** 알아서 정해집니다.

### `name` 과 `display-name` 은 다른 것입니다

- `name` — **식별용 평문 이름.** 색코드를 넣지 마세요.
- `display-name` — **표시용 이름.** 색코드를 넣습니다.

한 키로 쓰면 `&f[F] 물약` 과 실제 아이템의 평문 이름 `[F] 물약` 이 달라 식별이 조용히
깨집니다 — 물약을 마셨는데 회복이 안 됩니다.

## 낚싯대를 다른 플러그인이 공급하게 하기

`com.inmc.fishing.rod.RodSource` 를 구현하고 `Fishing.rods` 에 끼우면 됩니다.
요구하는 것은 셋뿐입니다.

```kotlin
class CustomItemRodSource(private val plugin: MyItemPlugin) : RodSource {
    override fun all(): List<Rod> = ...
    override fun byId(id: String?): Rod? = ...
    override fun identify(stack: ItemStack?): Rod? = ...
    override val editable: Boolean get() = false   // 우리 GUI 에서는 못 고친다고 알립니다
}

fishing.rods = CustomItemRodSource(myPlugin)
```

추첨·힘겨루기·로어·GUI 는 전부 이 인터페이스만 보고 있으므로 **낚시 쪽 코드는 한 줄도
바뀌지 않습니다.** `editable = false` 면 목록 화면의 만들기·지우기 버튼이 저절로 사라집니다.

`rods.yml` 을 읽고 쓰는 `RodRegistry` 는 그대로 남습니다 — 공급처를 바꿔도 설정 파일에 적힌
낚싯대는 계속 읽고 저장해야 하기 때문입니다.

## 2세대에서 바로잡은 것

| | |
|---|---|
| **대어** | 한 등급 승급 → **트로피 확정.** 최상위 등급에서 의미가 없었고 "대어"라는 이름과도 어긋났습니다. 지금은 크기를 트로피 구간에서 뽑습니다 |
| **피로도 상한** | 자연 회복이 절대 상한까지 찼습니다. 이제 `default` 까지만 차고, 그 위는 물약과 관리자 명령만 닿습니다 |
| **권한 보정** | `fishing.vip` 의 점을 YAML 이 경로로 읽어 **권한 보정이 통째로 사라져** 있었습니다 |
| **등급별 파일** | 물고기 등급이 파일 이름이라 등급을 바꾸려면 파일 사이로 옮겨야 했습니다. 지금은 필드입니다 |
| **오프라인 대회 보상** | 끝나는 순간 접속 중이 아니면 1등이어도 보상이 사라졌습니다 |
| **미끼·물약·생선살** | 세 종류 모두 GUI 로 관리할 수 있게 됐습니다 |
| **대회 사전 신청 저장** | 2세대는 진행 중인 대회만 저장해서, 시작 전에 재시작하면 참가비를 낸 신청이 사라졌습니다 |

2세대에 있었는데 5세대가 처음에 빠뜨렸다가 되살린 것(메인 화면·Shift+F, PlaceholderAPI,
WorldGuard 구역, 동시 대회·사전 신청·HUD, 연습 모드, 시작 연출, 결과 타이틀, 실패 유예,
관리 명령들, 낚싯대 로어 서식 …)은 `CHANGELOG.md` 에 표로 적어 두었습니다.

## 만들기

```bash
./gradlew :fishing:build
```

워크스페이스 루트에서 돌립니다. 결과는 `build/libs/inmc-fishing-1.0.0.jar` 입니다.

`inmc-core` 는 `includeBuild` 로 물려 있어 **루트 빌드는 core 의 테스트를 컴파일조차 하지
않습니다.** core 를 고쳤다면 따로 돌리세요.

```bash
cd inmc-core && ./gradlew test
```
